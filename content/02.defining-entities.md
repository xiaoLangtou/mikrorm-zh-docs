Entity 是简单的 JavaScript 对象（所谓 POJO），没有限制，也不需要继承基类。你也可以使用 [entity constructors](./entity-constructors.md)——它们不会在受管理的 Entity（从数据库加载的 Entity）上执行。每个 Entity 都必须有 primary key。

Entities are simple javascript objects (so called POJO) without restrictions and without the need to extend base classes. Using [entity constructors](./entity-constructors.md) works as well - they are never executed for managed entities (loaded from database). Every entity is required to have a primary key.

Entity 可以通过三种方式定义：

Entities can be defined in three ways:

- Decorator classes——Entity 的 attributes 以及每个 property 都通过 Decorators 提供。我们在 class 上使用 `@Entity()` Decorator。Entity properties 要么使用 `@Property` Decorator，要么使用引用 Decorators：`@ManyToOne`、`@OneToMany`、`@OneToOne` 与 `@ManyToMany`。参见完整的 [decorator reference](./decorators.md)。

- Decorated classes - the attributes of the entity, as well as each property are provided via decorators. We use `@Entity()` decorator on the class. Entity properties are decorated either with `@Property` decorator, or with one of reference decorators: `@ManyToOne`, `@OneToMany`, `@OneToOne` and `@ManyToMany`. Check out the full [decorator reference](./decorators.md).

- `EntitySchema` helper——通过 `EntitySchema` helper 以编程方式定义 schema。你既可以使用普通 class，也可以使用 interface。这种方式还允许复用部分 Entity 定义（例如 traits/mixins）。更多内容见 [通过 EntitySchema 定义 Entity](./entity-schema.md)。

- `EntitySchema` helper - With `EntitySchema` helper we define the schema programmatically. We can use regular classes as well as interfaces. This approach also allows to re-use partial entity definitions (e.g. traits/mixins). Read more about this in [Defining Entities via EntitySchema section](./entity-schema.md).

- `defineEntity` helper——基于 `EntitySchema`，利用 TypeScript 的类型推断能力自动推断 Entity interfaces。更多内容见 [`defineEntity` 章节](./entity-schema#defineentity)。

- `defineEntity` helper - Based on the `EntitySchema`, automatically infers entity interfaces using TypeScript's inference capabilities. Read more about this in [`defineEntity` section](./entity-schema#defineentity).

此外，如何从 Decorators 提取 Metadata 由 `MetadataProvider` 控制。两个主要的 metadata providers 是：

Moreover, how the metadata extraction from decorators happens is controlled via `MetadataProvider`. Two main metadata providers are:

- `ReflectMetadataProvider`——使用 `reflect-metadata` 读取 property types。更快，但更简单且更啰嗦。

- `ReflectMetadataProvider` - uses `reflect-metadata` to read the property types. Faster but simpler and more verbose.

- `TsMorphMetadataProvider`——使用 `ts-morph` 从 TypeScript 编译后的 API 读取类型信息。更重（需要完整 TS 作为依赖），但可以实现 DRY 的 Entity 定义。借助 `ts-morph`，我们可以按代码中定义的方式提取类型信息，包括 interface 名称以及属性的 optionality。

- `TsMorphMetadataProvider` - uses `ts-morph` to read the type information from the TypeScript compiled API. Heavier (requires full TS as a dependency), but allows DRY entity definition. With `ts-morph` we are able to extract the type as it is defined in the code, including interface names, as well as optionality of properties.

更多内容见 [Metadata Providers](./metadata-providers.md)。

Read more about them in the [Metadata Providers section](./metadata-providers.md).

如果你希望在 `em.create()` 等方法中把 nullable 字段变为必填（也就是不能省略该属性），可以使用 `RequiredNullable` type。这类属性在 `em.create()` 方法中必须显式提供，但允许传入 `null`。

## 默认值

我们可以通过两种方式为属性设置默认值：

We can set default value of a property in 2 ways:

1. 使用 property initializer。只要你不需要使用诸如 `now()` 这样的原生数据库函数，就应优先选择这种方式。采用该方式时，Entity 甚至会在真正持久化到数据库之前就拥有默认值（例如通过 `new Author()` 或 `em.create(Author, { ... })` 创建新 Entity 时）。

1. Use a property initializer. This approach should be preferred as long as we are not using any native database function like `now()`. With this approach our entities will have the default value set even before it is actually persisted into the database (e.g. when we instantiate new entity via `new Author()` or `em.create(Author, { ... })`).

> 这只有在你拥有实际的 Entity class（而不是 interface）时才可行。如果你使用不带 class 的 `EntitySchema`，或使用 `defineEntity` helper，则可以使用 `onCreate` 选项来设置默认值。注意：这会在 `flush` 期间处理，因此在 Entity 持久化之前，你无法在 Entity 实例上拿到默认值。从 v6.5 起，你可以使用 `processOnCreateHooksEarly` 配置项，让这些 hooks 在调用 `em.create` 时就立即运行。
>
> This is only possible if you have an actual entity class, not an interface. If you use `EntitySchema` without a class, or `defineEntity` helper, you can use the `onCreate` option to set the default value. Note that this is processed during `flush`, so the default value will not be available on the entity instance before it is persisted. Since v6.5, you can use the `processOnCreateHooksEarly` config option, to run those hooks right when `em.create` is called.

2. 使用 `@Property` Decorator 的 `default` 参数。采用该方式时，真正的默认值由数据库提供，并会在持久化（flush 之后）自动映射回 Entity 属性。要使用诸如 `now()` 这类 SQL functions，请使用 `defaultRaw`。

2. Use `default` parameter of `@Property` decorator. This way the actual default value will be provided by the database, and automatically mapped to the entity property after it is being persisted (after flush). To use SQL functions like `now()`, use `defaultRaw`.

> 从 v4 起，对于 SQL functions 你应使用 `defaultRaw`，因为当 `default` 的值为字符串时，它会被自动加引号。
>
> Since v4 you should use `defaultRaw` for SQL functions, as `default` with string values will be automatically quoted.
